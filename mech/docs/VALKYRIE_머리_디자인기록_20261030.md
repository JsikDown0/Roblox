## 2. 작업 흐름 — 효과가 있었던 것

### 2-1. Rodin 은 "설계도"로만 쓴다
- r1(컨셉만 보고 손으로 쌓음)은 "옆면이 너무 뚱뚱하고 컨셉보다 못생겼다" `[결정]` → 머리만 Rodin 으로 뽑아 옴(재질 있는 GLB · 없는 GLB · PBR/음영 GLB · 발광 마스크).
- GLB 를 Blender 축(x, −z, y)으로 바꾸고 칸 격자로 래스터화(numba `rast.py` · `view.py`) → **덩어리·옆 윤곽·색 구역의 기준**으로만 씀. 칸 단위 형태는 손으로 다시 짰다.
  - 환산: 16.5 칸/단위, z = 248 + (v − 0.8)·K, y = −5 + (v + 0.15)·K (`rodin_ref.py`).
  - 색 구역은 텍스처 색을 팔레트 등급(흰·남색·금·발광)으로 나눠 지도화(`rodin_colclass.py` · `rodin_facecol.py`).
- 확인 도구: r1 위에 Rodin 윤곽 겹쳐 보기(`rodin_vs_r1_overlay.png`), 옆 윤곽 비교(`side_compare_r1.png`).
- 스카디 때의 결론과 같다: Rodin 을 그대로 쓰면 AI 특유의 뭉개짐·불균형이 따라온다. **비율과 덩어리만 빌리고, 판·단차는 우리 방식으로** `[관찰]`.

### 2-2. 머리통 = 0° · 45° · 1:2 평면만 쓴 다면체 `[결정: Fable 방식]`
알(타원) 바탕(r2)은 계단이 지저분했다. r3 부터 머리통을 **평면 부등식의 교집합**으로 만들었다(`valk_head3.core`).
```
Z ≤ 258   Z−Y ≤ 264   Z+Y ≤ 265   Y ≤ 9   Y−Z ≤ −233   Z ≥ 236   Y ≥ −13
Z+2|x| ≤ 267   |x| ≤ 8   |x|−Z ≤ −235   |x|−Y ≤ 17   |x|+Y ≤ 15      (각 항에 +s 로 껍질 두께)
```
- 껍질 = core(s) − core(−2). 판 층은 같은 식에 s 를 바꿔 만든다(흰 판 1~3단).
- 경사가 45° 와 1:2 뿐이라 계단이 규칙적이고, 판 경계가 평면끼리 만나는 능선이 된다.

### 2-3. 비교 시트 + 칸 지도로 본다
- 시트: 컨셉 얼굴 | 지난 판 | 새 안들. 정면 확대 · 앞 30° · 옆 · 뒤 3/4 + **게임 크기 ×3~×4**(100 스터드). 유저는 게임 크기와 확대를 둘 다 본다 — "게임 크기 ×4 는 만족인데 확대하면 이상해" 가 실제로 나왔다.
- 칸 지도(`facemap.py`): 정면에서 본 맨 앞 칸의 **x · z · 깊이 · 색**을 글자로 찍는다. 원인 진단은 전부 이걸로 했다(흰 세로줄의 정체 · 마스크 돌출 · 후덕 원인 · 삐죽 칸).
- 섬 검사 · 칸 수 · 정면/뒤 색 비율(`check_head.py`)을 판마다 찍는다.

### 2-4. 다른 AI 피드백은 "재 보고 나서" 적용
- Fable 5.1 · GPT 피드백을 두 번 받았다. 읽고 → 유저와 상의 → 고른 것만 적용 `[결정]`.
- 재 보니 틀린 주장이 있었다(예: "뿔 20°", "볏·뿔이 앞으로 기울었다" — 실측과 다름) → 적용하지 않음.
- 유저가 정리해 준 지시서(r12: 유지 4 · 수정 4)는 항목마다 **원인을 먼저 재고** 고쳤다(5-6 참고).

### 2-5. 유저가 직접 칠해 오면 그대로 적용
r13 은 유저가 r12 정면 캡처에 눈 칸을 직접 칠해 온 것을 칸 위치로 환산해(x ±2, z 246) 그대로 넣었다. 말보다 정확하다.

## 5. 교훈 — 다음 기체 머리에 그대로 쓸 것

### 5-1. 인상은 윤곽보다 흰색 배치가 정한다 `[실측]`
- r7 → r8 에서 "왜 후덕해졌지?" — 정면 윤곽 폭을 z 236~252 **전 줄** 재 보니 r7 과 똑같았다. 바뀐 건 흰색뿐이었다.
  - r7: 기울어진 볼 가드가 눈꼬리(x ±6)에서 턱(±5)으로 내려가 마스크에 합쳐짐 = **턱으로 모이는 흰 V 선** → 날카로움.
  - r8 쐐기: 얼굴에서 가장 넓은 줄(z 245)의 가운데 흰 폭 7 → **15칸**(흰 가로 띠), 얼굴 아래 흰 비율 44.0 → 49.7% → 광대가 넓어 보임.
- 규칙: **얼굴 가장 넓은 줄에 흰 가로 띠를 깔지 않는다. 흰색은 사선으로 턱 쪽에 모은다(V).** 같은 줄이 흰색이어도 아래가 바로 V 로 좁아지면 후덕해지지 않는다(r9-4 에서 확인).
- 옆에 세운 흰 세로 띠(볼 가드)도 같은 이유로 후덕해 보였다 — "날카롭던 인상이 후덕해졌다" `[결정: 제거]`.

### 5-2. 흰 선이 눈을 지나가면 안 된다
r7 의 "눈을 세로로 가로지르는 흰 선" = 볼 가드를 roty 12° 로 기울인 판이었다(위는 x ±6 에서 눈 바깥을 덮고, 아래는 x ±5 에서 눈 밑을 지남). **기울인 판은 아래가 안쪽으로 들어온다** — 눈 근처 판은 정면 칸 지도로 눈 칸과 겹치는지부터 본다.

### 5-3. 눈을 감싸는 흰 바탕은 "사선 띠 + 눈도 같이 깎기"
- 가로 1줄 아래 눈꺼풀 → "할 거면 사선으로 깔고 눈도 그에 맞게 깎아야지" `[결정]`.
- 정답 형태: 흰 띠의 윗변·아랫변을 **둘 다** 1:2 사선으로(아랫변만 가로면 쐐기가 되어 5-1 의 후덕 띠가 된다), 눈 아랫변을 그 사선에 맞춰 깎는다.
- 두 눈은 **검정 다리로 떼어 놓는다**(가운데에 금 코 끝). 붙어 있으면 발광 번짐 때문에 한 줄 바이저처럼 읽힌다.
- **금 V 아랫변과 눈 사이에 검정 1칸 이상.** 눈이 금에 붙으면 눈썹 그늘이 사라진다.

### 5-4. 마스크(얼굴판)
- 마스크 앞면이 **금 코 끝과 같은 깊이면 입이 튀어나와 보인다** → 얼굴판 전체를 코 끝보다 한 칸 뒤로. "가운데만 톡 튀어나온" 판도 같은 증상 — 가운데를 얼굴 V 평면과 한 면으로 맞춘다.
- 코 밑보다 **아래가 넓어지는 육각 마스크 = 턱살.** 아래로 좁아지게(T1).
- 판 사이의 1~2칸 남색 틈은 확대하면 구멍·얼룩으로 보였다 → 메워서 한 장으로(r9-4).
- **입 모양(ㅅ 표시 등)은 넣지 않는다** — "우리 화풍으론 사람 얼굴처럼 보이기 쉽다" `[결정]`. 스타일 가이드 1-5 얼굴 함정 표에 추가할 항목.
- 턱: 뾰족(흰 V 가 한 점까지) vs 각짐(위에서 끊고 남색 턱 노출) — 둘 다 성립. 각짐은 흰 판이 남색 위에 따로 얹힌 판처럼 보여 입체감에 유리. VALKYRIE = 각짐, **뾰족은 다른 기체용으로 보관** `[결정]`.
- 검정 턱 블록은 정면에서 짙은 목 프레임과 섞여 안 보였고, 기각됐다.

### 5-5. 입체감 = 판을 접는다 (회전 파트)
- 컨셉의 "가운데 세로선에서 접혀 한쪽 밝고 한쪽 그늘" → 흰 판을 좌우 두 파트로 나눠 rotz ±15° (선례: Aero 얼굴 6차 P안 18°). 면이 평평해서 빛 받는 각도만 달라진다. 계단 접힘(칸을 한 칸씩 물림)은 세로 줄무늬 = 흰 수염 위험(Aero 3차).
- 15° vs 20°: 20° 가 명암 차이는 크지만, 15° 가 판 바깥 끝이 남색 턱보다 1.2칸 앞(20° 는 0.6칸)이라 판이 떠 보이는 맛이 있다 → 15° `[결정]`.
- ⚠️ **가운데 줄을 두 판이 둘 다 가지면 안 된다.** 같은 칸이 +15°/−15° 로 겹쳐 폭 1칸 띠 + 가는 선 = 딱딱한 세로 경계(r11). 정답: 가운데 1줄은 회전 없이 머리에 두고, 두 판은 |x| 1 부터 + 축을 판 안쪽 모서리(±0.5)로 → 모서리를 한 번 깎은 부드러운 능선(r12).
- 회전 판 앞에 머리 칸이 한 칸이라도 나와 있으면 판 위에 진짜 그림자를 드리운다(r12 의 눈 밑 띠 |x| 4~5). 판 둘레 칸 깊이를 판 앞면 깊이와 맞춘다.

### 5-6. 1칸이 눈에 띈다 (확대 기준)
- 45° 1칸 굵기 선은 칸이 모서리로만 이어져 **점선**으로 보인다 → 2칸 계단으로.
- 턱 끝 1칸 돌출("삐죽 칸"), 보석 위 꼭짓점 1칸, 볏 옆 흰 조각 같은 1~2칸 요소를 유저가 확대에서 하나하나 짚었다. 게임 크기에선 안 보여도 **확대 시트를 한 번은 칸 단위로 훑는다.**

### 5-7. 덜 다듬은 쪽이 맞을 때가 있다
뒤통수는 r2 A 의 세 판을 매끄럽게 이은 5안(r6)보다 **원본 그대로**가 "우리 게임에 제일 어울린다" `[결정]`. 스타일 가이드 2절 6번(복잡해지면 덜어낸다)과 같은 흐름 — 다듬기도 더하기의 일종이다.

### 5-8. 미리보기 렌더러의 그림자 얼룩
- 회전 파트 표면의 회색 삼각 무늬 = `vox_preview` 그림자 지도 해상도 부족(회전 면에서 계단 무늬). 모델 문제가 아니다.
- `vox_preview.render(..., shadow_res=8, shadow_k=8)` 로 올리면 대부분 사라진다(기본 2.5/3 — 10-30 추가한 인자, 기본값은 예전 그대로). 회전 파트가 있는 시트는 이 값으로 렌더해서 판단한다. 렌더 시간은 몇 배 늘어난다.
- 실제 모습은 Studio 조명에서 다시 본다.

### 5-9. 진행 방식
- 방법이 열려 있는 수정(예: "중앙 구분")은 **만들기 전에 방법 후보를 말로 정리해 고르게** 한다 — 이번엔 4안(접힌 두 판 · 가운데 홈 · 계단 접힘 · 능선 1줄)을 적고 1번으로 갔다.
- 원인은 단정하지 말고 칸 지도로 잰다. 이번에 칸 지도로 바로 잡힌 것: 흰 세로줄 = 볼 가드, 후덕 = 흰 가로 띠, 입 돌출 = 코 끝과 같은 깊이, 세로 경계 = 가운데 줄 겹침, 회색 면 = 렌더러 + 판보다 앞선 1칸.
- 고르는 것은 유저 몫. 추천은 근거와 함께 말하되 원안과 나란히 보여 준다.
