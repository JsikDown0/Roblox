# 로봇 차기작 — 현재 상태 (2026-10-24)

> **로봇 차기작 섹션** (`claude/로봇차기작/`): Roblox 메카 전투 게임. 원래 판매 에셋을 만들던 방에서 테스트로 시작했다가 커져서 10-24에 섹션을 분리했다. 판매 에셋(`claude/판매에셋/`)과는 별개 라인이다.
> 지금 단계: **조작감 프로토타입**. 기체 1종, PC 조작, 시험장 하나. 게임 규칙·모드는 아직 없다.

## 1. 콘셉트와 확정 사항 (유저 결정)
- 플레이어가 메카에 **탑승하면 메카가 곧 플레이어**다. 시야가 메카 기준으로 바뀌고, 피격 판정을 메카가 대신 받으며, 이동·사격·등 배기구 부스트를 쓴다. 기본 무장은 라이플.
- 모델은 **Claude가 Blender에서 직접 제작**한다. Tripo 로봇은 능력 체크용 예제(타인 제작)였고 게임에 쓰지 않는다(`판매에셋/차기에셋_신화크리처_20261024.md` 4절).
- 스타일: **복셀**로 기본형 메카를 만들었다(10-24, 매끄러운 스타일과 미형·게임 효율을 비교한 뒤).
- 플레이 피드백으로 정한 동작:
  - **한 손 사격**(유저 참고 이미지). 쏘지 않는 왼팔은 앞으로 내밀어 살짝 굽힌다.
  - 사격을 멈추면 **즉시** 원래 자세로 돌아온다(약 0.08초).
  - 부스트: 진행 방향으로 크게 수그리고 한쪽 발을 앞으로 내미는 런지. 부스트 중에 쏘면 **사격하는 오른팔만** 사격 자세가 된다.
  - 옆·뒤 이동은 다리를 옆으로 벌리지 않는다(X자 교차와 가위질처럼 보여 기각). 대신 **하체(골반)를 진행 방향으로 튼다**.
  - 크기 **2배**(키 약 21스터드). "가볍다"는 피드백으로 무게감(관성·느린 회전·발 디딤 충격)을 넣었고, 카메라 흔들림은 줄였다.
  - ❌ 사격 각도 제한(정면이 아니면 총이 안 나감)은 "답답하고 버그로 읽힌다"며 기각했다. → **상체 비틀기**로 대체(4-4).

## 3. Blender 복셀 엔진 — `mech_voxel.py` (10-24 밤 복구·재작성)
- **경위**: 처음 엔진은 Blender 세션 메모리(`driver_namespace`)에만 있어서 Blender를 끄자 사라졌다. 대화 기록도 압축돼 원본 코드는 회수할 수 없었다.
  - 엔진은 새로 짰다.
  - 형태는 mech.blend의 Mech_Basic 메시에서 **거꾸로 뽑아** 데이터로 저장했다.
- **보관 위치(3중)**
  - 바탕화면 `Roblox\mech_voxel\mech_voxel.py`(엔진)와 `mech_basic_vox.json`(형태 데이터, 19파트 56,434칸).
  - mech.blend 안 Text 블록 2개(같은 내용, fake user로 보존).
  - Blender 원본 메시 자체(언제든 다시 뽑을 수 있다).
- **검증(전부 일치)**
  - 데이터로 다시 만든 19파트를 원본과 대조했다.
    - 단위 면 28,298개의 위치·색
    - 쿼드 수
    - 피벗·부모 관계·월드 행렬
  - 역추출 품질 검사: 세 축 패리티 일치, 색 충돌 0.
  - 엔진의 GLB 내보내기를 원본 `Mech_Basic.glb`와 대조했다. 15메시 모두 삼각형(위치 + UV), 노드 이름, 메시 이름(`X_<파트>`), 변환이 같다(바이트 순서만 다름).
- **좌표 규칙(실측)**
  - 셀 크기 0.1 Blender 단위. 셀 i는 [i×0.1, (i+1)×0.1].
  - +X = 기체 왼쪽, −Y = 정면(라이플 방향), +Z = 위, 바닥 z=0.
  - 좌우 대칭면은 **x = 0.05**(셀 0의 중심)이고 대칭 셀은 i → −i다. 그런데 피벗은 0 기준(FootL 0.95 / FootR −0.95)이다. 원래 값을 그대로 보존한 것.
  - 격자 lo (−34, −62, 0) ~ hi (34, 26, 110). 밖이면 ValueError(음수 인덱스가 반대편으로 감겨 라이플이 등 뒤에 생긴 사고 방지).
- **팔레트 9색**(sRGB): 1 밝은 장갑 (214,218,222) / 2 중간 장갑 (128,139,152) / 3 어두운 프레임 (52,56,64) / 4 검정 프레임 (30,32,38) / 5 주황 포인트 (255,120,24) / 6 청록 발광 (90,230,255) / 7 주황 발광 (255,140,30) / 8 금색 (240,200,60) / 9 빨강 발광 (235,50,60).
  - 발광은 6·7·9(세기 5 / 6 / 3).
  - 팔레트 PNG의 색 n 블록 = (n % 8, 7 − n // 8). 픽셀 행은 아래부터 센다.
- **API**
  - 불러오기: `Vox.load(json)`. 파트 편집은 `with v.part("Head"):` 안에서 한다.
  - 편집: `box` / `carve` / `paint`와 좌우 대칭판 `mbox` / `mcarve` / `mpaint`. 범위는 양끝 포함 셀 번호다.
  - `mirror_part(src, dst)`: 파트를 좌우로 뒤집어 복사.
  - 오브젝트 생성: `v.build("컬렉션")`. 파트별 오브젝트, 원점 = 피벗, 재질 MECH_1~9, 부모 연결.
  - 저장: `v.save(json)`. 역추출: `read_objects("Mech_Basic")`.
  - 로블록스용 내보내기: `export_glb(v, 경로)`. 팔레트 UV, 합칠 파트 합침, `<이름>_parts.json`에 피벗을 따로 쓴다.
  - 사용 예는 파일 맨 위 주석에 있다.
- **추정값 주의**: 겉에서 안 보이는 속 칸(약 3.4만 칸)의 색은 메시에 정보가 없어서 가까운 겉 칸 색으로 채웠다. 화면엔 영향이 없지만, 크게 파내면 원래와 다른 색이 드러날 수 있다.
- 아직 다시 안 만든 것: 계단식 모따기 `bbox`·`outline`·`stripes` 같은 모델링 보조 함수, 렌더 헬퍼(`cc_render2`·`set_pose`). 새 기체를 만들 때 다시 짠다.
- ⚠️ 부모 지정 전에 반드시 `view_layer.update()`(엔진에 반영됨). 낡은 `matrix_world` 때문에 기체가 뒤섞인 적이 있다.
- ⚠️ 앞으로 새 헬퍼는 **반드시 파일로 저장한 뒤** 불러 쓴다. Blender 메모리에만 두지 않는다. Blender MCP 애드온 서버(localhost:9876)가 켜져 있어야 한다.

### 3-1. Blender → Roblox 변환 (실측)
- glTF +Z 정면이 Roblox −Z가 된다. 축 변환: Roblox = (−x_b, z_b, y_b) + offset.
- GLB의 메시 데이터 이름은 `X_<파트>`다. 임포터가 이 이름으로 자기 RootPart에 `X_*Motor6D` 관절을 덧붙인다 → **지울 것**.
- 임포터는 `MeshPart.TextureID`를 채운다.
- `Model:ScaleTo(2)`는 Humanoid HipHeight와 파티클 이미터 크기까지 같이 키운다(2배 확대 때 확인).

### 4-2. 동작 구조
- **탑승(board, 서버)**
  1. 속도를 0으로 만들고 고정을 푼다.
  2. `player.Character = mech`로 바꾸고 `SetNetworkOwner(player)`.
  3. 원래 몸은 `ServerStorage.MechPilots/<UserId>`에 보관한다.
  - 하차는 F키. 몸은 옆 12스터드에 내려놓고 메카는 park한다(AimYaw·AimPitch 0으로 초기화).
- **스폰**
  - 템플릿을 복제해 패드 윗면 + RootHeight에 놓는다(`PivotTo`, PrimaryPart 기준).
  - FallingDown·Ragdoll 상태를 끄고 "Mech" 태그를 붙인다.
  - 감독 루프가 BayPad 24스터드 안에 빈 기체 하나를 유지한다. MaxMechs 6.
  - 사망하면 폭발 후 제거, RespawnDelay 6초.
- **카메라(클라)**: Scriptable 어깨 카메라 + 마우스 LockCenter. 피치는 −55~65°. 벽에 닿으면 당긴다.
- **몸 방향**: AlignOrientation(비강체, Responsiveness·MaxAngularVelocity 제한).
  - 사격·조준 중에는 AimTurnRate로 빨리 돈다.
  - 매 프레임 CFrame을 덮어쓰면 고속 이동 때 떤다.
- **관성**: 컨트롤 단계 뒤에 `Humanoid:Move`를 덮어쓴다(Accel / Decel).
  - 입력: 기본 조작 모듈(PlayerModule)이 있으면 `controls:GetMoveVector()`를 쓴다(키보드·패드·모바일). 없으면 `rawMove`가 WASD·방향키를 직접 읽는다.
  - 옛 플레이스엔 PlayerModule이 없어서 `rawMove` 경로로 개발했다. 새 플레이스는 PlayerModule 경로를 탈 가능성이 높다.
- **부스트**: 수평만 잡는 `LinearVelocity`(Plane 모드)를 BoostTime 동안 건다. 높이는 Humanoid에 맡긴다(위아래로 싸우면 떨림).
  - 공중이면 BoostLift를 준다. 화면 연출은 FOV +9.
  - 서버는 에너지를 깎고 `BoostUntil` 속성을 기록한다.
- **사격**
  - 클라는 화면 중앙 조준점을 향해 총구에서 레이캐스트로 이펙트를 그리고 `MechFire(target)`을 보낸다.
  - 서버 검사: 연사 제한 → 기체 정면 기준 각도 `FireArc + 20` 초과면 거부 → 총구에서 레이캐스트 → `TakeDamage`.
  - 서버가 `MechFX:FireAllClients("fire", …)`로 다른 클라에 이펙트를 뿌린다.
- **애니메이션: 전부 코드(절차적)**
  - 클라마다 RenderStepped에서 "Mech" 태그가 붙은 모든 기체의 `Motor6D.Transform`을 계산한다. 업로드할 애니메이션 에셋이 없다.
  - 남의 기체는 속성(AimPitch, AimYaw, BoostUntil, Energy)과 MechFX로 상태를 받아 같은 식으로 그린다.

### 4-4. 애니메이션 세부 (MechClient)
- 상태 블렌드: 조준 `k`(약 0.08초에 올리고 내림), 부스트 `kb`(smoothstep).
  - 남의 기체는 마지막 발사 후 0.25초 동안 조준 자세를 유지한다(AIM_HOLD_REMOTE, 연사 간격을 메우는 값).
- 걷기
  - 위상은 걷기 속도 / StrideLength로 돌린다. 부스트 중에는 위상을 멈춘다(부스트 속도로 돌리면 초당 열몇 번 흔들린다).
  - 발 디딤은 cos 부호가 바뀌는 순간이다. 이때 쿵 소리·먼지·카메라 흔들림·골반이 툭 꺼지는 연출이 붙는다.
  - 착지 충격은 0.3초 넘게 떠 있었을 때만 낸다.
- 방향별 이동: `legYaw`로 골반을 진행 방향으로 최대 65° 튼다. 상체는 허리로 되돌려 정면을 유지한다. 뒤쪽(100° 초과)은 골반을 돌리지 않고 뒷걸음한다.
- 상체 비틀기
  - 조준 방향과 기체 정면의 차이(`aimYawOff`)만큼 허리가 먼저 돈다(최대 TwistLimit 100°).
  - 남는 각도는 팔이 ±25° 안에서 보정한다.
  - 발사 허용 각도는 FireArc 120°.
- 부스트 자세
  - 하체를 부스트 방향으로 최대 80° 틀고 그 방향으로 런지한다. 상체는 허리로 정면을 유지한다.
  - 뒤로 부스트(110° 초과)하면 상체를 젖히고 미끄러진다.
  - 오른팔은 숙인 각도를 보정해 총구 피치 = 조준각이 되게 맞춘다.
- 축 규칙(모델 기준): X+ = 팔다리를 앞으로·상체를 뒤로 젖힘 / Y+ = 왼쪽으로 돎 / Z+ = 팔다리를 오른쪽으로. 라이플은 아래팔과 나란하다(총구 피치 = 허리X + 어깨X + 팔꿈치X − 90).

### 4-5. 조작 (PC 기준)
WASD 이동 · 마우스 시점 · 좌클릭 사격 · 우클릭 조준 · Shift/Q 부스트 · F 하차 · E(0.3초 홀드) 탑승

## 5. 고친 문제와 교훈
| 증상 | 실제 원인 | 해결 |
|---|---|---|
| E를 눌러도 반응 없음 | MechTemplate이 아직 없어 서버가 무한 대기 | 템플릿 생성 |
| 총을 개머리판 끝으로 쥠 | Grip 축 방향 | Grip C0 X축 −90° |
| 두 손 파지가 안 닿음 | 팔 길이·각도 | 유저 참고 이미지대로 한 손 사격 |
| 부스트 때 몸이 덜덜 떨림 | 걷기 위상이 부스트 속도로 돌고, 루트 CFrame을 매 프레임 덮어씀 | 부스트 중 위상 정지 + AlignOrientation + Plane LinearVelocity |
| 옆걸음 X자 교차 → 가위질 | 다리를 옆으로 벌리는 방식 자체 | 골반(legYaw)을 진행 방향으로 틀기 |
| 옆 부스트 때 다리가 양옆으로 찢어짐 | 같은 원인 | 하체를 부스트 방향으로 틀고 런지 |
| 앞을 보는데 뒤로 총알이 나감 | 몸 회전 지연 중 카메라 방향으로 발사 | 각도 게이트 → "답답하다"는 피드백 → 상체 비틀기 + 넓은 FireArc |
| 탑승 시 BayPad 아래로 잠겨 못 움직임 | **FallingDown 상태**: 넘어짐·래그돌 상태에선 HipHeight가 몸을 받쳐 주지 않음 | 조종 클라와 서버 양쪽에서 FallingDown·Ragdoll 끄기 + Running 강제 |
| PlayerModule 무한 대기 | 옛 플레이스엔 PlayerModule이 없었음 | WaitForChild 타임아웃 + `rawMove` 폴백 |
| Blender 재실행 후 메카 엔진 소실 | 엔진을 메모리(`driver_namespace`)에만 둠 | 메시에서 역추출 + 엔진 재작성, 파일·.blend 안에 저장(3절) |
| 내보낸 GLB 노드가 `Pelvis.001` | 같은 이름의 오브젝트(Mech_Export)가 이미 있음 | 내보내는 동안만 기존 이름을 비켜 둠(엔진에 반영) |

- **잠김 사건의 교훈**: 첫 가설(가짜 착지 애니메이션)은 틀렸다. `[MechDiag]` 진단 로그로 상태 값을 찍고 나서야 FallingDown이 드러났다. 프로젝트 지침 "원인을 단정하기 전에"와 같은 이야기다. 진단 로그는 확인 후 지웠다.
- Humanoid 상태 기계는 **네트워크 소유자(조종 클라)** 가 돌린다. 상태를 막으려면 클라에서도 막아야 한다.

## 6. 알려진 한계 / 미검증
- 이사는 유저가 성공을 확인했다(10-24). 다만 PlayerModule 이동 입력 경로(4-2)와 상체 비틀기(TwistLimit 100 / FireArc 120)를 따로 점검했는지는 기록이 없다. 이동·조준이 이상하면 여기부터 본다.
- 서버는 휴식 자세(rest pose)만 본다(Transform은 복제되지 않음). 그래서 서버의 피격·총구 위치 판정은 애니메이션 자세가 아니라 휴식 자세 기준이다. 대전용으로 가면 판정 박스를 별도로 설계해야 한다.
- 사격·부스트 등 액션 키는 PC 입력만 있다. 이동은 PlayerModule 경로로 가면 패드·모바일도 받지만, 액션 버튼은 아직 없다.
- legYaw 최대 65°인데 옆 이동은 90°라서 옆걸음 때 발이 약간 미끄러져 보일 수 있다.
- 적 AI, 기체 종류, 무기 종류, 게임 모드·규칙, 커스터마이즈는 **전부 미정**이다.

## 7. 작업 메모
- Studio: Play 모드를 임의로 시작하지 않는다(플레이 테스트는 유저가 하고 로그·영상을 준다). 스크린샷은 필요할 때만, 요청 안 한 설정은 바꾸지 않는다.
- 동작 피드백은 영상이 가장 정확하다. 프레임을 뽑아 자세를 읽었다.
- 기체 수치는 MechConfig 한 곳에서 조절한다(주석에 단위·의미 있음).
- 플레이스 간 이사는 "하위 폴더 이름 = 들어갈 서비스" 폴더 + 설치 모듈 형태가 편했다. 붙여넣기는 ServerStorage에 한다(Workspace 안의 Script는 실행된다).
- PC로 파일을 보낼 때(Claude 쪽 메모): 같은 파일 이름으로 다시 올리면 **이전 내용이 써지는 경우가 있었다**. 판마다 새 이름으로 올리고, 받은 쪽에서 파일 크기를 확인한다.
