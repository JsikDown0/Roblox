## 2. 실측으로 확인된 것
- **래그돌**: 굴러가는 시체 수 ↔ 물리 시간 상관 0.90, 1구당 약 1.3ms [계산, 거친 값]. 살아 있는 NPC 수와는 상관 거의 0. 상한 후 동시 래그돌은 6을 안 넘었다.
- **살아 있는 휴머노이드 병사 110~130명 = 물리 11~15ms**(60fps 예산 16.7ms). 지금 구조로는 병사를 못 늘린다 → 데이터 병사가 필요한 근거.
- **무쌍**: 컷인·카메라 구간은 평소와 같음. 회전 타격 순간 맞은 적이 0~1명이어도 프레임 +20~35ms(2/2). 한 번에 11킬이면 99~151ms → 사망 처리 스크립트가 무거움(1명당 약 10ms [계산, 표본 1]). 컷인 끝 190ms 튐 1회(5번 중 1번, 원인 모름). → 데이터 병사로 가면 사망 처리 구조가 바뀌므로 지금 구조에선 더 안 판다(유저 결정).
- **물결 생성은 이미 1프레임 1명**(AttackWaveSpawner SPAWN_PER_FRAME = 1). 내가 "한 프레임에 다 만든다"고 한 건 틀렸다.

## 6. 함정 (이번에 새로 밝혀진 것)
- **MCP 가 "connection timeout" 을 내는 진짜 원인 하나 = 반환 문자열의 깨진 UTF-8.** 한글을 `l:sub(1, n)` 처럼 바이트로 자르면 글자가 중간에 잘려 응답이 안 만들어진다. `return ("가나다"):sub(1,4)` 한 줄로 재현됨. 자를 땐 `utf8.len` 이 성공하는 지점까지 줄여서 자른다. (플레이 중 timeout 이력 중 일부도 이것이었을 수 있다 [추측])
- execute_luau 로 스크립트 소스를 넣을 때 소스 안에 `]]` 가 있으면 바깥은 `[===[ ]===]` 로 감싼다.
- 9월 하네스 규칙: HB 는 문턱 감지기(정확한 값 아님) · 기준 재측정으로 드리프트 확인 · 표적은 더미 · 플레이어는 가만히.
- 시체 수는 "휴머 − 살아 있는 NPC"로 세면 굳은 시체까지 섞인다 → 속성 CorpseFrozen 으로 나눠 센다.
