## 1. 이케아 구조 = 우리 루프

```
실제 이케아   2F 쇼룸에서 전시품 만져봄 → 가격표에 '통로·칸 번호'
              → 1F 셀프 창고에서 납작한 상자를 카트에 → 계산대 → 집에서 조립
우리 루프     공급처 → 카트 운반 → 집(언덕 위) → 개봉 → 깐 물건이 바닥에 남음
```
이케아는 스킨이 아니라 **구조째 대응**된다. 1F 창고 / 2F 쇼룸의 층 구조가 기존 언덕(짐 싣고 오르는 과적 체감 구간)과 같은 자리.

## 2. 아이디어 조각

| # | 조각 | 만드는 필요 / 근거 |
|---|---|---|
| 1 | **층 구조 = 기존 언덕** — 1F 창고 / 2F 쇼룸, 카트용 경사 무빙워크 **모양**의 경사로 | 과적 체감 구간. ⚠️ 자동 이동은 X (v4 9절 탑승·자동화 금지) |
| 2 | **쇼룸 부스 = 집** — 이케아 모델룸처럼 부스가 동선을 따라 늘어섬, 깐 물건이 부스를 채움 | 남의 수집품이 돌아가는 길 위에 놓임 → 구경이 선택지가 아니라 동선이 됨 (v4 2절: 선택지로 주면 효율에 밀린다) |
| 3 | **전시품 = 뽑기 미리보기, 가격표 = 창고 위치** — 공용 전시대에 이번 입고 상자의 결과물(일반·광택·무지개)을 밟아볼 수 있게, 가격표 "통로 C · 칸 12" | "찾으러 간다"는 필요가 구조에서 생김 (v4 7-2: 구조 → 동사) |
| 4 | **통로 = 입고 로테이션 판** — 통로마다 바닥 재질이 다름(전자제품=키캡, 포장=뽁뽁이, 러그=푹신) | v5 유력 후보 '공급처 로테이션'의 공간 구현. 가까운/먼 통로가 매번 바뀌어 고정 최적 루트가 안 생김 |
| 5 | **계산대 = 음향 세트피스** (선택) — 셀프 계산대 바코드 '삑' | v4 4절 "무엇을 파는가" 미결과 이어질 수 있는 자리 |
| 6 | **폐점 후 매장** (분위기 로테이션) — 불 꺼진 새벽 매장 = 리미널 스페이스 | 위협 없이 '밤'을 분위기로만. 경비원을 넣으면 v5 긴장 후보가 되지만 호러 쪽으로 기울 위험 |

**과장 문법이 더하는 것**
- **매장 에셋은 원래 크기 그대로** 들어간다 (사람·매장 = 현실 비율, 물건만 거대).
- **거대 물건 = 매장 안 이정표.** "거대 스테이플러가 서 있는 통로가 C". 매장의 판촉용 대형 전시물로도 자연스럽게 읽힘. 입고 통로 위에 이번 입고품을 거대하게 세우면 목적지가 멀리서 보인다.
- **부스 크기는 물건 크기에서 역산**해야 한다. 스테이플러 한 대가 바닥 3.4×8.4 [기록 v5 실측], 카탈로그 간격으로 세 대면 폭 13.4. 깐 물건이 쌓이는 구조라 부스는 금방 찬다 → **공간 부족이 성장 축(부스 확장)이 될 수 있다.** v4 4절 "무엇을 파는가" 빈자리 후보 [추측].

**SCP-3008 연상 위험** — 로블록스의 "무한 이케아" 생존 게임. 가져온 에셋에는 실제로 SCP 로고가 박혀 있었다(8절). 밝은 낮 매장 = 거리 두기 / 밤 매장 = 연상 끌어오기.

## 3. 거주 형태 — 분리형 vs 매장 안 부스형 [미결]

**[권고] 부스형 + 원형 메자닌** (설계 판단, 측정 아님)

부스형이 나은 이유
1. 남의 수집품이 가는 길 위에 놓인다 (조각 2).
2. 매장 에셋 하나로 끝난다. 분리형은 주택 에셋 + 두 구역을 잇는 바깥 길(그 바닥도 ASMR 재질)이 새로 필요 — 1인 개발에서 차이가 큼.
3. "이케아 쇼룸에 사는 사람들"이라는 판타지가 뚜렷하고, 폐점 후 밤 매장과 이어진다.

분리형의 실제 장점
- 집과 바깥의 대비 — 과적으로 언덕을 오르는 긴장이 안전한 집에서 끝나는 맛.
- 개인 부지는 익숙한 문법이라 신규 유저가 바로 이해.
- 부지가 흩어져 스트리밍에 유리 [추측].

부스형의 핵심 문제 = **거리 공평성**
- 일렬 복도: 구경 효과 최대, 경사로 앞 부스와 끝 부스의 운반 거리가 다름 → 상자당 보상이면 끝 부스가 계속 손해. 로테이션으로 일부만 상쇄.
- **원형 메자닌**: 1F 창고 가운데가 뚫려 있고 경사로가 중앙으로 올라오며 부스가 둘레를 두름 → 모든 부스까지 거리가 같다. 구경 효과는 중앙 광장(공용 전시대)으로 보완.

곁다리: 소인 스케일의 "선반 칸 하나가 내 집" 안은 과장 문법 결정으로 폐기.

## 4. 원형 메자닌 대략 치수 (8부스)

```
가정   부스 앞 폭 W = 20   (스테이플러 세 대 폭 13.4 + 여유)
       물건 하나가 차지하는 바닥 ≈ 50   (스테이플러 3.4×8.4 + 틈)

광장 반지름    = 8 × W / 2π        = 25.5   → 광장 지름 51
부스 깊이 20   바깥 반지름 45.5    뒤 폭 35.7   면적 ≈ 560   물건 ≈ 10개
부스 깊이 40   바깥 반지름 65.5    뒤 폭 51.4   면적 ≈ 1430  물건 ≈ 25개
전체 지름      91 (시작) → 131 (최대 확장)      ※ 지금 테스트 맵 수평 경로 96과 비슷한 규모
```

설계 포인트
- **확장은 폭이 아니라 깊이로.** 앞 폭 고정 → 광장 크기 불변, 모든 부스까지 거리 = 광장 반지름(25.5) 유지. 부채꼴이라 뒤로 갈수록 확장 1단계당 면적이 커짐. 건물은 처음부터 최대 깊이로 짓고 확장 전엔 잠긴 구역으로 보여줌(확장 욕구의 미끼).
- **경사로는 광장 한가운데로.** 부스 사이 틈으로 들어오면 도착점에서 각 부스까지 거리가 0~51로 벌어진다. 1F에서 메자닌 아래를 지나 광장 중앙 구멍으로 올라오는 형태. 높이차 24·26.6°·머리 위 여유 8 가정 시 **광장 바닥 구멍 길이 ≈ 16** → 지름 51 광장에 들어감.
- 2F 바닥 높이의 하한은 메자닌 아래 랙 높이 (랙을 그 밑에 둔다면).

## 5. 바닥(키캡) 배치

**결론: 두 형태 모두 "반복해서 걷는 길에만 깐다" — 거주 형태와 무관.**
면적을 실제로 늘리는 건 부스형이 아니라 **입고 로테이션**(매번 목적지가 바뀌니 모든 통로에 깔아야 함).

```
키캡: MeshPart 2.70, 간격 3.00 → 바닥 9당 1개                [실측]
광장 (반지름 25.5)            ≈ 230개
경사로 (지금 _Hill)           = 192개                        [기록]
통로 6개 × 길이 40 × 폭 3칸   ≈ 240개                        [가정]
───────────────────────────────────
동선 합계                     ≈ 660개   (지금 맵 504개 [기록])
부스 8개 최대 확장 전부       ≈ 1,270개  ← 부스에 깔면 이게 제일 큼
```

- **성능은 문제 아님** [코드 읽음] — `_KeyWalk.nearestCap`은 전체를 훑지 않고 발밑 반경 3.2만 `GetPartBoundsInRadius`. 총 개수가 늘어도 한 걸음 비용은 그대로. 부담은 파트 수·제작량.
- **지금은 키캡이 아닌 바닥은 무음** [코드 읽음] — `StepSound`도 KeyCap 칸을 거쳐야 소리가 남.

**바닥 3등급 안**
1. **눌리는 칸 바닥** (키캡·뽁뽁이) — 칸마다 눌림·발광. 광장·경사로·통로(동선)에만.
2. **소리만 나는 판 바닥** — 큰 파트 하나 + 걸음 소리. 현재 경로 없음 → 작은 추가 작업 필요.
3. **부스 바닥** — 기본은 2등급, 눌리는 칸 바닥은 치장용 판매 (v4 4-2 발소리 팩 9~59 Robux와 같은 매대). 부스 안 ASMR은 원래 깐 물건들이 맡음.
→ 부스형이어도 키캡 수는 지금 맵의 약 1.3배.

## 6. 가져온 IKEA 에셋 분석 [실측]

### 6-1. 정체 — 다른 게임의 맵으로 보임 [추측, 근거 있음]
- 스크립트 6개 전부 내용이 `-- Decompiling is disabled` 한 줄 → 남의 게임을 통째로 저장하는 도구가 소스를 못 읽었을 때 남기는 자리표시로 보임.
- 원래 게임의 맵 규격: `GameMode = KOTH`, `ControlPoint`, 스폰 15개, `Objectives`, `SafeRoom`, 값만 저장된 `Settings.Lighting`.
- `solid_####` 파트 수천 개 + `furnituredresser001a` 같은 이름 → Source 엔진(하프라이프2 계열) 맵 변환 흔적 [추측].
- `SCP logo` 메시, `N.I.T. WORLDWIDE SHIPPERS UNION` 간판 → SCP-3008 세계관.
- 실제 "IKEA" 상표 텍스트는 없음 (Showroom·Checkout·Marketplace 등 일반명사).
- ⚠️ 툴박스 출처라면 올린 사람이 원작자인지 확인 필요. 아니면 출시 후 신고 시 게임 단위 문제 가능.
- **→ 프로토타입 뼈대·치수 샘플로 쓰고, 출시용은 그 치수로 새로 짓는다** [권고].

| RemoteEvent / BindableEvent | 4 / 2개 삭제 (문·오프너용) |

| 조명 | 255개(Point 129 / Spot 126, 그림자 141) 중 237개 끔(18개는 원래 꺼져 있었음, 어느 것인지 미기록) → 이후 **천장 주광 SpotLight 51개만 다시 켬** |

조명 재점등 규칙: 천장 등기구(LightBar 114 + Model 12)의 주광 SpotLight 중 서로 **35 이상** 떨어진 것만 → 1F쪽 25 / 2F쪽 26. 보조 PointLight(밝기 0.1)와 빨간 표시등 3개는 꺼둠.

**아직 남은 짐**: PathfindingModifier 2,472개, SurfaceGui 265개 (우리 게임엔 불필요).

**조명 미결** — 더 어두우면 ① 간격 25로 줄여 75개 켜기, 또는 ② `Lighting.Ambient` 올리기. 현재 (70,70,70), 지운 맵 원래 설정은 (200,200,200) — 원래 게임에서 내부가 밝았던 건 이 값 때문일 가능성 [추측]. 성능엔 유리하지만 **전역 설정이라 기존 키캡 맵도 같이 밝아짐**.

## 7. 맵 크기

**[결정] 줄인다** — 샌드웨이퍼 체감: "한 바퀴가 현실 쇼핑 시간과 비슷".

줄여야 하는 이유
1. **같은 길을 수십 번 오가는 구조.** 복잡함은 첫 1회만 탐험, 이후엔 마찰. 이케아 동선은 손님을 오래 머물게 하려고 일부러 돌아가게 만든 걸로 알려져 있음 — 우리 목적과 정반대.
2. **맵 크기 = 한 번 나르는 시간.** 지금 테스트 맵 편도 = 수평 96 + 언덕 53.7 ≈ 10초 [기록 v4]. IKEA 맵은 창고 랙 중심(X≈595)→쇼룸(X≈365) 수평만 약 230 → **2.4배** [실측 좌표로 계산]. 분리형이면 여기에 집까지 길이 더 붙음.
3. **리얼감은 면적이 아니라 높이와 표식에서.** 31.7 높이 랙, 통로 번호 간판, 천장 조명 줄, 계산대. 걷는 거리 = 바닥 면적, "크다"는 느낌 = 높이 → **좁고 높게**.

형태별로 남길 것
- **분리형**: 매장은 받아 가는 곳 → 창고 통로 몇 줄(로테이션용) + 계산대 + 입구 전시대. 쇼룸·모델룸·도크·세이프룸·컨테이너 야드 제외.
- **부스형**: 2F 쇼룸(부스) + 창고 + 경사로. 도크·세이프룸·컨테이너·중복 계산대 제외.

### 부스트(이동속도) 논의
- 장르에서 이상한 해법 아님 — `+1 Speed ASMR Keys` (v4 7-3), v4 4-1 판매 후보에 이동속도 있음.
- 우리 게임에선 빨리 걸어도 ASMR이 줄지 않고 **초당 딸깍이 늘어남** → 시간을 건너뛰게 하는 게 아니라 소리를 촘촘하게 만드는 상품. 콘텐츠를 깎지 않는다.
- ⚠️ 다만 **맵 크기는 기본 속도 기준**. 부스트 전제로 크게 지으면 신규 유저가 첫 판부터 현실 쇼핑 시간을 걷는다 = "편하려면 돈" (v4 0-2 A안의 "안전하려면 돈"과 같은 구조).
- 부스트는 **더 풍성하게** 쪽으로: 기본 속도로도 즐겁고, 부스트면 더 빠르고 촘촘하게. 초기 수익 후보 Rewarded Video(광고 보고 잠깐 부스트)와 맞음.
- **속도 성장형이면 큰 맵도 살릴 수 있다**: 처음엔 가까운 통로만 → 속도가 붙을수록 먼 통로·큰 매장 구역이 열림. 과적 감속을 속도 업그레이드가 상쇄하는 구도도 자연스럽게 생김. 단 **첫 구역은 기본 속도에 맞춘 크기**여야 함.

## 8. 미결 / 다음 할 일 (순서대로)

1. **거주 형태 결정** — 분리형 vs 부스형. 이게 매장에 무엇이 들어가야 하는지를 정한다.
   - 싸게 확인하는 법 (v4 7-1 붙여서 판단): 경사로 위에 가짜 부스 2~3개 + 스테이플러 하나씩 → 돌아오는 길에 남의 부스에 들어가 밟게 되는지.
2. **편도 목표 시간** — 기본 속도(v4 기록 16) 기준. F5로 지금 테스트 맵 한 바퀴와 IKEA 맵 창고→쇼룸 구간을 각각 걸어 보고 "한 번 더 나르고 싶은" 길이를 고른다.
3. **매장 크기 산출** — 2의 결과 × 기본 속도. IKEA 맵이 첫 구역인지 나중에 열리는 먼 구역인지도 여기서 나눈다.
4. **그레이박스** — IKEA 맵에서 랙 한 줄·통로 폭(12~20)·층고(24)만 떼어 와 작은 매장을 새로 짠다.
5. 곁가지 미결
   - IKEA 에셋 출처 확인 (툴박스 업로더 = 원작자인지)

   - PathfindingModifier·SurfaceGui 정리 여부
   - 걸어서 넘을 수 있는 높이 한계 — 아직 안 잼
