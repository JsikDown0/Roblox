### 0-1. 왜 문제인가 `[실측]`

우리 수익 설계(4절)는 **카트 용량·안정성 판매**가 핵심인데,
`Shift` 하나가 그 매대를 통째로 무력화한다. 과적해도 천천히 가면 안전하니까.

**벤치마크 대조** `[실측]`:
```
Unbox ASMR!   축: 시간 ←→ 가치.  "좋은 상자일수록 개봉이 오래 걸린다"
              → 그 시간을 돈으로 산다 (Quick Unlock 199 / Auto Roll 249 / Fast Conveyor 175)
우리          축: 위험 ←→ 시간.  Shift 로 교환 끝. 돈 낼 자리가 없다
```

🔴 **두 게임 다 축이 하나인데, 저쪽은 그 축에 과금을 걸었고 우리는 무료 버튼을 줬다.**

⚠️ **감속만 계속 너프하는 건 방향이 아니다** `[결정]`.
그건 Shift 를 약하게 만드는 것이지 업그레이드를 매력적으로 만드는 게 아니다.

## 8. 기술 함정 (재발 방지)

**8-1. 카트 기울기 축** `[경험 신규]`
`POSE_Y=180` 이라 Z 축 기울기는 진행방향과 나란해 **안 보인다.**
✅ `Angles(0, yaw+POSE_Y, 0) * Angles(0,0,lean) * Angles(POSE_X,0,POSE_Z)` — yaw 뒤 독립 축.
⚠️ 카트 폭이 2 스터드라 **5도는 끝단이 0.09 스터드**. 안 보인다. 22도는 되어야 읽힌다.

**8-2. 경사 63도 튐** `[경험 신규]`
램프는 26.6도인데 모서리에서 레이가 옆면을 맞아 **63도**가 찍히고
내리막 push 161 이 튀어 즉사했다.
✅ `if slopeRad > MAX_SLOPE_RAD then slopeRad = 0 end` (35도 상한)
→ 인계의 *"제외 목록보다 결과 보장"* 형태. 뭘 맞았는지 안 따지고 결과를 보장.

**8-3. 오르막은 속도² 비례여야 한다** `[경험 신규]`
선형이면 속도 12.7 이든 11.6 이든 push 가 같아 **'천천히'가 선택지가 안 된다.**
내리막은 이미 속도² 였는데 오르막만 선형이라 한쪽만 무서웠다.

**8-4. 게이지 유예(SPILL_HOLD)는 거짓말을 만든다** `[경험]`
0.25초 유예 → HUD 는 100% 인데 안 쏟김. `0.0` 으로.
단, 게이지가 너무 빨리 차면(0.45초) 예고 역할을 못 한다. **속도와 유예를 같이 봐야 한다.**

**8-5. 일괄 치환(gsub)이 의도 밖을 바꿈** — 앵커를 길게. 8-4·7-4 참조.

**8-6. 카트 자세 3단계 오염** — Y는 진행방향 전용, 자세는 속성에 고정.
⚠️ F5 런타임의 CFrame 대입은 Workspace 에 남아 에딧모드까지 오염.

**8-7. 좌표계를 새로 만들지 말 것** — `cart.CFrame * CFrame.new(o)` 로 직접 곱한다.

**8-8. 참조 카운트 대신 집합** — `holders[cell] = { [주체]=true }`

**8-9. 지수 평활의 정상상태 지연** — `오차 ≈ v × dt × (1-α)/α`
✅ FOLLOW_DIST + LEAD_TIME + **MIN_GAP 하드 클램프**

**8-10. 대량 파트 :Destroy() 는 모바일 렉** — `LOOT_CAP = 200`, 오래된 것부터 회수.

**8-11. 유령 파트** `[경험]` — 구 place 에 y=-15~-75 로 Cap 720 + Plate 720 + Wall 20 이
`CanCollide=true` 로 5층 쌓여 있었다. 툴박스 모델 잔재. **새 place 로 이사하며 해소.**

## 10. 모바일 `[경험]`

```
입력   ContextActionService:BindAction(..., true, ...)  ← 3번째 true = 모바일 버튼
HUD    상단 중앙, 너비 62%, TextScaled 10~18
버튼   카트 / 싣기 / 내리기 / 천천히  (우측 세로 배치)
```

⚠️ `UserInputService.InputBegan` + `KeyCode` 만 쓰면 **모바일에서 영원히 발동 안 함.**

🔴 **조이스틱은 아날로그라 중간 속도가 자연히 나온다.**
`MoveDirection.Magnitude` 가 0~1 로 오므로 "천천히"가 모바일에선 이미 가능.
Shift 는 PC 를 모바일 수준으로 맞추는 보정일 뿐.

**미확인 `[미결]`:** 폰에서 조이스틱 미세 조절이 실제로 되는지.
(리서치 경고: "가상 조이스틱이 둔하고 손가락이 화면을 가린다")
